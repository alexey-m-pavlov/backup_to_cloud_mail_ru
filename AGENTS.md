# AGENTS.md

Правила работы над проектом для людей и AI-агентов.

## О проекте

`Backup-ToCloudMailRu` — PowerShell-скрипт резервного копирования локальных
папок в Cloud@mail.ru через rclone. Скрипт запускается из Планировщика задач
Windows. Документация и комментарии в коде ведутся на русском языке.

## Workflow по Issue

Каждая задача оформляется как GitHub Issue в
`alexey-m-pavlov/backup_to_cloud_mail_ru`.

1. **Создать Issue** с описанием проблемы. Для воспроизводимых проблем
   указывайте:

   - симптом и код ошибки;
   - окружение (версия Windows, способ установки PowerShell, режим задачи);
   - причину или гипотезу;
   - обходное решение;
   - что предлагается изменить в репозитории.

   ```bash
   gh issue create --repo alexey-m-pavlov/backup_to_cloud_mail_ru \
     --title "<краткий заголовок>" --body-file <файл>
   ```

2. **Создать ветку** от `master`. Имя — `feature/IssueN`, где `N` — номер
   Issue:

   ```bash
   git checkout -b feature/Issue1
   ```

3. **Внести изменения и обновить документацию.** Если меняется поведение,
   пути или настройка, изменения должны попасть в `README.md` в том же
   коммите.

4. **Сделать коммит.** Формат сообщения:

   ```
   [Issue N] Short English summary
   ```

   - `N` — номер Issue;
   - далее одна короткая ёмкая строка на английском;
   - без точки в конце.

   Примеры:

   ```
   [Issue 1] Document full pwsh.exe path for Task Scheduler
   [Issue 2] Add retry for HTTP 400 errors
   [Issue 3] Fix log rotation on month boundary
   ```

5. **Запушить ветку и открыть Pull Request**, указав в описании `Closes #N`.

## Безопасность и обезличивание

Не коммитить:

- `backup.config.json` — локальные пути и настройки машины;
- `secrets/`, `rclone.conf`, `rclone-credential.xml`, `*.sec`;
- логи (`logs/`, `*.log`) и `rclone-backup.lock`.

Выгрузки заданий Планировщика (`*.xml`) и другие артефакты с данными
машины перед коммитом **обезличивать**:

- имя пользователя и домен → `DOMAIN\User`;
- SID пользователя → `S-1-5-21-0000000000-0000000000-0000000000-1001`;
- реальные домашние каталоги и имена машин → заглушки.

Структуру XML и путь к проекту (`C:\Scripts\backup_to_cloud_mail_ru`)
можно оставлять — он используется в документации как пример.

## Стиль документации

- Язык — русский, тон — технический и нейтральный.
- Заголовки и списки в Markdown, пути и команды — в блоках кода.
- В `README.md` поддерживать актуальными оглавление и таблицу состава
  проекта при добавлении файлов.
- Для ошибок указывать код (`0x80070002`) и точный текст сообщения.

## Проверки перед коммитом

```bash
git status --short
git diff
```

Убедитесь, что в diff нет секретов, реальных имён пользователей, логов и
локальной конфигурации.

## Известные особенности

- **PowerShell и Планировщик задач.** `winget` устанавливает PowerShell как
  MSIX-пакет и регистрирует псевдоним приложения. После обновления короткое
  имя `pwsh.exe` может не разрешаться в неинтерактивной сессии, и задача
  падает с `0x80070002`. В действии задачи указывайте полный путь:

  ```
  "%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe"
  ```

  Подробности — в `README.md`, раздел «Запуск из Планировщика задач».

- **Пример задания.** `backup_to_cloud_mail_ru.xml` — обезличенная выгрузка
  задания с корректным путём к `pwsh.exe`. При изменении способа запуска
  обновляйте и XML, и README.
